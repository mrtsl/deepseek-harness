# LAN SSH Remote Environments Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add LAN SSH hosts as product-managed remote environments for workspace creation, directory browsing and session execution.

**Architecture:** Add a Host SSH host manager above the existing helper-backed `dsh-ssh` provider, expose it through generated Remote namespaces, then thread workspace environment identity through the Workspace registry and UI. Local workspace behavior remains the default; SSH workspaces route filesystem, subprocess, sandbox and terminal operations through an isolated execution stack for the selected host.

**Tech Stack:** TypeScript, Cordis services, Typert Remote controllers, storage-domain persistence, OpenSSH, React slot UI, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-27-lan-ssh-design.md`

## Global Constraints

- The feature is LAN-only: no public relay, mobile takeover, hosted tunnel or internet exposure.
- Users add hosts manually; automatic LAN discovery and default `~/.ssh/config` import are out of scope.
- Authentication must delegate to local OpenSSH and support automatic, config alias, key and password/passphrase askpass flows.
- Credentials never enter workspace records, settings descriptors, model-visible logs or client-visible diagnostics.
- This release supports Linux and macOS SSH targets; remote Windows targets are out of scope.
- Local workspaces keep source-compatible behavior by treating a missing workspace environment as local.
- SSH directory browsing uses a separate Remote namespace and separate workspace slot, not environment parameters on the local directory-picker namespace.

## Review Focus

- Host-key failures: Task 2 tests direct hosts keep strict host-key checking and surface `ssh-host/host-key-refused`.
- Password/passphrase flows: Task 2 tests askpass environment construction and asserts the secret is absent from argv and diagnostics.
- Remote path validation: Task 5 tests SSH workspace creation rejects relative paths and remote Windows-style paths.
- Lost transport: Task 2 tests a connected host transitions to `failed` when the underlying `SshConnection.failed` becomes set.
- Local regression: Task 6 tests old directory-flow occupants that call `onPicked('/path')` still create local workspaces.
